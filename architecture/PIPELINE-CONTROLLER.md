# Host focus controller

*[Deutsch](PIPELINE-CONTROLLER.de.md)*

`HostController` drives the existing `HostLocalArbiter` and `BACHFacade`. It does
not create a second durable job queue. Research/compute, model-backed services,
video, Blender and builds use the same socket/slot protocol; original native
executors remain responsible for their jobs, input limits and checkpoints.

## Configuration and polling

Create the existing host writer, arbiter, sensor and reviewed executor adapters
first. The controller accepts one immutable tuple of `ControllerClient` entries.
Each client has an explicit socket scope, priority floor and permission to submit
interactive requests. Only an operator client may override ordering. A client
token is randomly generated by default, omitted from repr and never put in status
or audit output. Applications must distribute tokens privately; there is no new
network transport, credential file, service installation or hidden polling thread.
This is a cooperative local capability boundary, not isolation from arbitrary
Python code executing in the same process.

```python
from ocean_resources import ControllerClient, FocusPolicy, HostController

worker = ControllerClient("compute-worker", frozenset({"compute"}), priority_floor=3)
chat = ControllerClient("chat", frozenset({"local-model"}), allow_interactive=True)
operator = ControllerClient("operator", frozenset({"compute", "local-model"}),
                            operator=True, allow_interactive=True)
controller = HostController(existing_facade, (worker, chat, operator),
                            FocusPolicy(idle_seconds=30, interactive_slice_seconds=120,
                                        background_min_seconds=10))
# The existing explicit host loop calls tick more often than heartbeat_ttl.
result = controller.tick(operator.client_id, operator.token)
```

Default audit output is appended and fsynced to `<host>.focus-audit.jsonl` in the
existing host-local writer directory. The writer must still be held. Linked or
replaced audit files, failed writes and a 16 MiB archival threshold fail closed.
An injected audit sink must be trusted, bounded and non-reentrant. No token is
included. Status reports queued requests, active grant, handoff state and errors.
Status reads and ordinary heartbeats are not user activity.
Start intent is audited before executor admission. A failed completion audit
keeps the controller HOLD until a successful audit-restored record reconciles
the still-owned grant; a later heartbeat cannot silently clear this fault.
The recovery record retains the exact failed event, including the original grant
and requeue decision after a successful release. It does not fabricate a new grant.

## Handoff, idle and fairness

1. `submit(client_id, token, request)` delegates to the arbiter's immutable,
   idempotent request contract and retains the native planner/executor pointer.
2. `tick()` requests safe return when an interactive or higher-priority request
   needs a background slot. The existing facade alone obtains the application
   checkpoint, stops/unloads its own execution, verifies exit and RAM release,
   and obtains a newer independent capacity readback.
3. A model caller brackets an active turn with `begin_turn(..., grant, turn_id)`
   and `end_turn(...)`. A return request prevents new turns; an in-flight turn
   may finish. No active inference is forcibly killed. The native adapter must
   still attest application quiescence before releasing memory.
   Completed and active turn IDs share a bounded history; capacity is reserved
   before begin_turn, so every admitted turn can finish even at the boundary.
4. Idle chat ends with `requeue=False`. New genuine input must create a new
   native request/idempotency identity; conversation state stays application-owned.
   A bounded interactive slice also requests return when other work waits.
5. After the arbiter's maximum consecutive chat grants, its selected background
   grant receives the configured minimum runtime before another chat can displace
   it. An operator override may alter this focus ordering. These timers bound
   scheduling opportunities, not the latency of an unbounded native model call.

Lifecycle callbacks run outside the controller state mutex. Concurrent polls
observe the transition instead of duplicating checkpoint/start work. A failed
handoff retains its exact grant and requeue decision for retry. A failed start
retains the arbiter reservation and is never adopted from a status/PID file.
An unresolved restart journal remains HOLD pending independent reconciliation.

## Operator override

`override(client_id, token, OverrideCommand(...))` requires an operator credential
and binds the command to host, current writer session, existing waiting request,
reason, unique command ID and a future expiry within the arbiter's configured
maximum. An exact replay neither renews nor reapplies a consumed command;
different content under the same ID is rejected. A null request clears ordering.
The audited command changes priority selection only: profile, physical reserve,
budget, task claim, checkpoint and publication gates remain in force.

`finish(..., grant)` is restricted to the request's native client or an operator.
It runs the same verified return protocol; it cannot turn an outstanding retry
from requeue into completion. A heartbeat timeout never clears residency itself.

## Acceptance boundary

Behavioural tests cover compute → chat → idle → compute, genuine background
runtime under sustained chat pressure, authentication, replay, concurrency,
callback re-entry, failed capacity retry and retained failed-start reservations.
A real small owned-process test checkpoints at 7, hands off and resumes to 14.
Its capacity/profile inputs are fixtures; it does not qualify a large model or
prove the live Buddha chat. Production workload profiles, native client wiring,
transport/UI, restart reconciliation and controlled cutover remain separate gates.
